## Repository Structure

Each student creates three individual text files:

- STUDENTID_gb.txt — Information about George Brown College.
- STUDENTID_devops.txt — Information about the COMP3104 DevOps course.
- STUDENTID_sdlc.txt — Importance of DevOps in the Software Development Life Cycle.

## Branching Strategy

The master branch contains the integrated group project.

Each group member works on an individual branch using the format STUDENTID-Name.

Members make at least 10 meaningful commits on their branches before submitting their work through pull requests.

Pull requests are reviewed and merged into master after successful validation.

## Continuous Integration

The repository uses GitHub Actions for continuous integration.

The workflow is located at .github/workflows/ci.yml.

The workflow runs automatically when changes are pushed to master or when a pull request targets master.

It checks that README.md exists and reports whether the validation succeeds.

## Pull Request Process

1. Create a separate branch.
2. Make changes locally.
3. Commit changes using meaningful messages.
4. Push the branch to GitHub.
5. Open a pull request targeting master.
6. Review the changes and verify GitHub Actions passes.
7. Merge the pull request into master.

A pull request template is provided in .github/PULL_REQUEST_TEMPLATE.md.
